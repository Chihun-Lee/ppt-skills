# ppt — 다목적 발표·보고 PPT (v4.1 공개판)

이 폴더 하나에 엔진(`lib/kims_ppt.py`), 로고 자리 채우기(`lib/logo_slots.py`), 검사기(`scripts/check.py`), 바탕 파일(`template/base.pptx`), 기준서(`STANDARD.md`), Paperlogy 글꼴(`fonts/`)이 모두 들어 있다. 엔진 파일 이름의 `kims`는 원작 틀의 이름일 뿐이고, 공개판 바탕 파일에는 기관 로고·사진이 없다.

- **`<스킬>`** = 이 SKILL.md가 있는 폴더(스킬을 불러올 때 안내되는 Base directory). 명령과 build.py에는 실제 절대경로를 넣는다.
- **기준서(SSOT)**: `<스킬>/STANDARD.md` — 크기·간격·색·글자량·게이트 수치는 모두 여기에 있다. 이 문서는 절차와 API만 다룬다.
- **발표용**(발표·학회·세미나) = `Deck("ppt")`(이 문서) · **보고용** = `Deck("report")` → `<스킬>/REPORT.md`의 차이를 더한다.

## 0. 처음 한 번

### 0.1 첫 사용 안내 (사용자가 이 스킬 묶음을 처음 쓸 때)
```bash
python "<스킬>/scripts/logo.py" status          # Windows 는 python 대신 py 일 수 있다
```
`첫 사용 안내: 아직`이면 PPT를 만들기 전에 사용자에게 아래 두 가지를 **한 번에** 묻는다(요청 내용으로 어느 쪽인지 뻔해 보여도 처음 한 번은 묻는다).

1. **어떤 PPT인가** — 이 묶음에는 두 가지가 있다.
   - **① 다목적 PPT** (이 스킬 `ppt`): 발표·학회·세미나·내부 회의 발표자료, 그리고 발표 없이 읽히는 보고자료. 표지·목차·간지·그림 중심 본문·감사 장
   - **② 실험결과 정리 PPT** (형제 스킬 `ppt_experiment`): 실험 조건·환경·결과를 표·그래프·사진·`key : value`로만 나열하는 데이터 공유용. 문장·표지·장식 없음
2. **로고** — 표지·간지·감사·본문 오른쪽 위에 들어갈 로고 그림 파일(PNG·JPG·SVG·PDF)이 있는가. 파일이 없으면 기관·팀 이름만 받아 글자 로고를 만들 수 있고, 둘 다 없으면 `LOGO`라고 적힌 자리표시 그림이 들어간다(나중에 바꿀 수 있다). ②는 원래 로고를 넣지 않는 양식이다.

답을 받으면 기록한다.
```bash
python "<스킬>/scripts/logo.py" set "<로고 파일>"      # 파일을 받았을 때
python "<스킬>/scripts/logo.py" text "기관·팀 이름"    # 이름만 받았을 때
python "<스킬>/scripts/logo.py" placeholder            # 없다고 했을 때(기본값과 같다)
python "<스킬>/scripts/logo.py" welcomed               # 안내를 마쳤다고 기록
```
②를 고르면 형제 스킬 `ppt_experiment`(보통 `<스킬>/../ppt_experiment/SKILL.md`)를 읽고 그 절차로 간다. 두 번째부터는 묻지 않고 요청 내용으로 고른다. 애매하면(예: "실험 결과로 학회 발표") 한 줄로 확인한다.

### 0.2 로고 바꾸기 (언제든)
- 사용자 기본값: 위 `logo.py set / text / placeholder / none`(none = 로고 없음). 설정은 `~/.ppt_skills/config.json`
- 덱 하나만 다르게: `Deck("ppt", workdir=HERE, logo=HERE / "assets" / "partner_logo.png")` (`"placeholder"`, `"none"`도 된다)
- 견본 보기: `python "<스킬>/scripts/logo.py" preview --out logo_preview.png`(표지·본문·간지·감사 4장)
- 로고는 비율을 지킨 채 자리 상자(본문 오른쪽 위 304×46px, 표지 520×220px, 간지 330×54px, 감사 400×64px @1920 격자) 안에 최대 크기로 들어간다. 흰 여백·투명 여백은 `logo.py set`이 잘라 낸다. 300px보다 작은 로고는 표지에서 흐릴 수 있으니 더 큰 파일이나 SVG를 받는다.
- 다른 기관·회사 로고는 그 기관 발표이거나 사용 허락을 받은 경우에만 쓴다.

### 0.3 환경 점검
```bash
python "<스킬>/scripts/doctor.py"
```
- 패키지·글꼴·LibreOffice·로고 설정을 점검한다. ✗ 항목은 저장소 `INSTALL.md`(또는 `<스킬>/README.md`)대로 고친다(설치 명령은 사용자에게 보여 주고 동의를 받은 뒤 실행).

- 엔진·검사기·바탕 파일은 고치지 않는다. 덱마다 엔진을 복사하지도 않는다.

## 1. 한 줄 정의

> **한 장 = 목차 항목명 그대로인 제목 바 + 짧은 중간제목 1줄(■, 그 장의 주제 이름표) + 큰 그림·표·도식 + 결과 위주 세부(•) 0~4줄**

PPT는 보고서가 아니다. 글은 적게, 그림은 크게. 말로 채울 것은 발표자가 말한다.

## 2. 입력 처리
- 모호하면 **분량(발표 시간) · 청중 · 자료 위치** 세 가지만 한 번 묻고 진행한다.
- **학회 발표**: 발표 시간(구두 10~15분이면 본문 10~14장), 국내·국제 여부를 확인한다. 국제 학회라도 영어 덱은 사용자가 원할 때만 만들고(STANDARD §7), 논문·포스터 그림은 원본 figure를 패널 단위로 잘라 쓴다(9절).
- 자료(사진·논문 figure·데이터·기존 덱)는 **먼저 읽어** 수치와 그림 목록을 확보한다. 자료에 없는 수치·문장을 지어내지 않는다. 자료끼리 수치가 다르면 원자료(측정 파일·DB) > 최근 보고서 > 메일·메모 순으로 따르고, 고른 값·버린 값·이유를 완료 보고에 적는다.
- 사용자가 직접 고친 pptx가 있으면 10절을 따른다(새로 만들어 덮어쓰지 않는다).

## 3. 작업 위치와 산출물
- **덱 폴더** = 사용자 작업 폴더 아래 `<덱 이름>/`. 스킬 폴더 안에는 만들지 않는다.
  ```
  <덱 이름>/
  ├── build.py          덱 정의(4·6절)
  ├── assets/           쓸 그림 사본 + manifest.csv(파일, 원본 경로, 출처, 캡션)
  ├── output/           <이름>.pptx + <이름>_미리보기.pdf   ← 전달물
  └── render/           미리보기 PDF·PNG·컨택트시트(자동 생성)
  ```
- **이미 건넨 pptx는 같은 이름으로 다시 저장하지 않는다.** 고칠 때마다 `_v2`, `_v3`로 저장한다. 저장 전에 같은 폴더에 `~$<파일명>`(PowerPoint 잠금 파일)이 있으면 파일이 열려 있는 것이므로 멈추고 사용자에게 알린다. 열린 파일을 덮어쓰면 PowerPoint 창의 그림이 전부 X 상자로 바뀌고 사용자가 고친 내용도 사라진다.

## 4. 절차

1. **자료 목록**: 쓸 그림을 `assets/`에 복사하고 `manifest.csv`를 만든다. 실사진·실측 그래프·논문 figure가 먼저다.
2. **목차**: 챕터 2~4개 × 섹션(= 본문 제목 바 문자열). 섹션당 1~3장. 같은 섹션의 연속 장은 **같은 제목 문자열**을 쓴다. 본문 장 수는 **발표 시간을 주면 분 × 0.8~1**(5분이면 4~5장), 시간을 안 주면 12~16장. 10분 이하 발표는 목차·간지를 빼도 되고, 그때도 `d.slide(..., chapter=n)`의 챕터 번호는 그대로 쓴다(제목 탭 번호).
3. **장별 중간제목(■) 1줄 = 짧은 주제 이름표**: 명사구 8~20자. 결론·수치·날짜·괄호 설명·→ 연쇄를 넣지 않는다.
   - 좋은 예: `성과지표 6종 정리 및 현황` · `자동 데이터 분석 모듈 도입계획` · `인장 데이터 수집 현황` · `2차 실측과 예측 비교`
   - 나쁜 예: `성과지표 6종 중 장비 충족, AI 정확도는 기준 협의 필요` · `로봇팔 도입 완료(7/20), 연마기는 3차년도 계획`
   - 그 장의 결론·수치는 **세부 첫 줄·표·그림·캡션**에 둔다. 중간제목에서 빼면서 정보가 사라지면 안 된다(게이트 G7이 → 연쇄·날짜를 fail, 22자 초과를 warn으로 잡는다).
4. **모듈 선택**(5절)과 `build.py` 작성(6절).
5. **빌드·렌더·검사**: `python "<스킬>/scripts/make.py" <덱 폴더>`
   - `LayoutError`·`WrapError` = 넘침. **글자를 줄이지 말고 문안을 줄이거나 장을 나눈다.** 엔진에는 자동 축소가 없다.
   - `[warn] 본문 아래 빈 공간` = 그림·표를 키우거나(`fill=True`) 도식을 더한다. 글로 채우지 않는다.
   - 게이트 fail 0이 될 때까지 고친다. warn은 읽고 판단한다.
   - **증분이 기본**: 2회차부터 게이트는 처음 보는 장·고친 장·지난 fail 장만 출력한다(fail은 항상). 전 장은 `make.py --full`. 판단 끝에 받아들인 fail은 `python "<스킬>/scripts/review_state.py" mark <pptx> --accept 1-6`.
6. **시각 점검**(7절): **1회차**는 `render/contact.png`로 덱 흐름을 보고 `render/png/slide-NN.png` 전 장을 직접 연다. **2회차부터는 `make.py` 끝에 나오는 '다음 회차 N쪽' 목록의 PNG만** 본다. 본 장은 `review_state.py mark <pptx> --ok 3,5-7`, 걸린 장은 `--flag "9=이유"`로 남기고 목록이 빌 때까지 고친다. 경계는 `python "<스킬>/scripts/zoom.py" render/<덱>.pdf <쪽> x y w h`로 확대해서 본다.
7. **전달**: `make.py`가 렌더 PDF를 pptx 옆(`output/<이름>_미리보기.pdf`)에 복사한다. **그 PDF를 사용자에게 열어 보여 준다**(Mac `open`, Windows `start ""`). 보고에는 pptx·PDF 경로, 장 수, 게이트 결과, 뺀 내용, 남은 주의점을 쓴다.

## 5. 모듈 (STANDARD §9.5·§11)

| 쓰는 때 | 코드 | 엔진이 하는 일 |
|---|---|---|
| 표지 | `d.cover(제목, 행사·날짜, [소속, 이름])` | 원형 복제, 제목 40pt ≤2줄(`\n`으로 줄 지정). 둘째 줄이 한두 어절뿐이면 고아 줄(G6 fail)이니 두 줄 길이를 비슷하게 끊는다. 로고는 오른쪽 자리에 자동 |
| 목차 | `d.toc([(챕터, [섹션...]), ...], front=[], back=[])` | 챕터별 세로 열. 섹션 = 제목 바 문자열. 챕터 밖 장(요약·References)은 `front`·`back`에 번호 없이 |
| 간지 | `d.divider(번호, 챕터명)` | 원형 복제, 번호 80pt 두 톤 |
| 본문 장 | `s = d.slide(제목, chapter=n, kind=None)` | 제목 바 28pt + 챕터 탭. `kind="summary"`·`"conclusion"`은 요약·결론 장 |
| 중간제목(요지) | `s.key("…")` | ■ 24pt 1줄, 짧은 이름표. 바로 뒤 전폭 불릿과 한 상자로 합친다 |
| 세부 | `s.bullets(["…", "…"])` | • 20pt, 항목당 1줄 |
| 글+그림 | `s.text_figure(items, 그림, 캡션)` | 그림 왼쪽 + 설명 오른쪽, 가로로 긴 그림은 설명 위·그림 아래(면적 큰 쪽) |
| 그림 1장 | `s.figure(그림, 캡션)` | 남은 영역에 최대로(비율 유지) |
| 그림 2~4장 | `s.figures([(그림, 캡션), ...])` | 한 줄 / 1+2 / 2×2 중 그림 면적이 큰 배치 |
| 사진+설명 | `s.photo(사진, 캡션, [설명 2~4줄])` | 사진 크게(크롭 20%까지) + 오른쪽 설명 |
| 표 | `s.table(머리, 행, fill=False)` | 줄 확정·행 높이 계산. 자연 폭이 본문 50% 넘으면 전폭. 안 들어갈 때만 밀집(14pt). `fill=True`면 행마다 +0.5줄까지 |
| 좌우 분할 | `with s.row([3, 2]) as (L, R): …(rect=L) …(rect=R)` | 한 흐름 블록. 짧은 칸이 높은 칸의 50% 이상이면 윗선, 미만이면 세로 가운데(`valign="t"/"m"`) |
| 칸 안 세로 쌓기 | `r = s.table(..., rect=L); s.bullets([...], rect=s.below(r, L))` | 앞 모듈 아래 남은 칸 |
| 비교 | `s.compare((현행, [줄]), (개선, [줄]))` | 필 카드 2개(회색·#546882) |
| 병렬 카드 | `s.cards([(제목, [줄]), ...], fill=False)` | 등폭·등높이 필 카드. `fill=True`는 이웃 칸과 높이를 맞출 때만 |
| 단계 | `s.flow([(단계, 설명), ...])` | 번호 붙은 옅은 면 상자 + 셰브런(5단계까지) |
| 일정 | `s.timeline([(날짜, 내용), ...], orient="v"/"h")` | 점·선 일정표 |
| 결론 박스 | `s.note("한 줄 결론")` | 주황 테두리. **`kind="summary"`·`"conclusion"` 장 전용** |
| 메시지 장 | `s.message("…")` | 요지 가운데 정렬. 덱당 2장 이하 |
| 출처 | `s.source("Lee et al., Addit. Manuf. 81, 104012 (2025)")` | 우하단 1줄. 논문·외부 figure 인용 장에만 |
| 참고문헌 | `d.references([...])` | 인용 3편 이상이면. 14pt |
| 발표자 노트 | `s.notes("…")` | 화면에 안 보임. 기본은 비워 둔다(8절) |
| 감사 | `d.closing()` | 원형 복제 |
| 저장 | `d.save(HERE / "output" / "이름.pptx")` | 경고 출력 + 엔진 메타(검사기용) |

- 같은 구성이 3장 넘게 이어지면 게이트가 알린다(같은 제목 구간은 예외).
- 장 수는 본문 장 기준이다. 표지·목차·간지·감사는 따로 센다. 10분 이하 발표는 목차·간지를 생략할 수 있다.

## 6. API

```python
import sys; sys.path.insert(0, r"<스킬>/lib")      # ← 실제 절대경로로 바꾼다
from pathlib import Path
from kims_ppt import Deck, Rect, FRAME, chart_figsize, mpl_style

HERE = Path(__file__).resolve().parent
A = HERE / "assets"
```

- 좌표는 1920×1080 px 격자. 글 요소 프레임 `FRAME` = x 120~1800, y 162~1008. `Rect(x, y, w, h)`.
- `s.body()` = 다음 모듈이 놓일 영역(보류 중인 요지가 있으면 그 아래). 그래프는 `chart_figsize(s.body())`로 슬롯 크기를 잰다.
- **칸 폭과 글자 수**: 전폭 3카드 한 줄 ≈ 470px(20pt 한글 약 12자), 2/3 칸 안 2카드 ≈ 408px(약 11자). 5단계 흐름은 상자 안쪽 약 240px(16pt 굵은 한글 약 8자)라 두 어절 단계 제목이 줄바꿈되면 고아 줄(G6 fail)이 된다.
- `rect`를 주지 않은 모듈은 요지 아래로 자동으로 쌓인다(블록 간격 48px). 묶음이 짧으면 엔진이 조금 내리고, 너무 짧으면 요지에 붙여 두고 경고한다.
- `row()` 칸 안의 `s.bullets([...], rect=칸)`은 칸 왼쪽선에서 시작한다. 요지와 세부 묶음이면 `(요지, [세부...])` 튜플로.
- `rect=`를 준 모듈은 커서를 옮기지 않는다. 좌우 배치는 반드시 `with s.row(...)`로 감싼다. `row()` 밖에서 `rect=`로 직접 놓은 요소가 있으면 그 장은 세로 이동을 하지 않는다(겹침 방지).
- 줄바꿈은 엔진이 어절 단위로 정한다. 꼭 붙일 어구는 NBSP(`" "`)로 묶거나 `\n`으로 줄 위치를 정한다. 숫자+단위(`1,221 MPa`)와 짧은 라벨+값(`경도 45`)은 자동으로 묶인다.
- 그리스 문자(α, β, σ, Δ)는 그대로 쓴다(엔진이 Arial로 분리). ²·³·₂는 위·아래첨자로, μ는 µ로, ℃는 °C로 자동 변환된다. ✓·★는 쓰지 않는다.
- **matplotlib 그래프**: `import matplotlib as mpl; mpl.rcParams.update(mpl_style())`, `fig = plt.figure(figsize=chart_figsize(슬롯 Rect))`로 **슬롯 크기 그대로** 그리고 `fig.savefig(path, dpi=200)`(`bbox_inches="tight"` 금지). 그림 속 글자가 실제 12~14pt가 된다. 축·범례는 영어, 한국어는 슬라이드 캡션에만.
- **네이티브 차트**(데이터 편집 가능, 9절 권장): 칸 하나를 차트에 통째로 준다. 예시는 `<스킬>/examples/demo/build.py`의 `native_chart()`.
  ```python
  from pptx.chart.data import XyChartData
  from pptx.enum.chart import XL_CHART_TYPE
  from kims_ppt import E
  from native import chart_fonts
  with s.row([1, 1]) as (L, R):
      s.bullets(["…"], rect=L)
      cd = XyChartData(); ser = cd.add_series("Measured")
      for x, y in pts: ser.add_data_point(x, y)
      gf = s.s.shapes.add_chart(XL_CHART_TYPE.XY_SCATTER, E(R.x), E(R.y), E(R.w), E(R.h), cd)
      chart_fonts(gf.chart, 14)                 # Arial 14pt. 축 ID 는 d.save 가 고친다
      gf.chart.has_title = False                # 계열 하나짜리 차트는 계열명이 제목으로 뜬다 — 제목은 캡션·요지로
  ```

## 7. 시각 점검 항목 (게이트가 못 보는 것)
1. 그림 속 글자(범례·눈금·라벨·스케일바)가 14pt 이상으로 읽히는가. 글자가 박힌 논문 그림은 데이터 부분만 잘라 쓰고 글자는 PPT 글상자로 다시 쓴다. 원자료가 있으면 다시 그린다
2. 잘린 글자, 인접 패널 조각, 그림 속 em dash·깨진 기호가 없는가
3. 중간제목이 짧은 이름표인가(결론·수치·날짜·→ 없음), 빠진 결론이 세부·표·그림에 있는가, 제목이 목차와 같은가
4. 강조가 한 곳인가(색 글씨·굵은 덩어리 없음)
5. 애매한 빈 공간이 없는가, 글 칸이 그림 옆에서 너무 짧지 않은가
6. 같은 역할 요소가 같은 위치·크기인가(장 사이 리듬), 표 정렬이 덱 안에서 같은가
7. 사진·캡처가 흐리지 않은가

## 8. 문안 규칙 (STANDARD §7 요약)
- 명사(구) 종결. 마침표·`-다`·질문형 없음. 비유·경구·"X가 아니라 Y" 금지.
- **세부는 결과 위주 쉬운 말**: "무엇을 몇 개 했고 결과가 어떤지"부터. 현황은 `1차 102개 중 102개 완료`, `2차 78개 요청, 24개 완료, 18개 제작 중`처럼 개수로.
- **작업 날짜(월/일)는 뺀다**: 본문에 7/20 같은 날짜를 쓰지 않는다. 일정 장·행사 일시·표의 일정 열만 예외. 표지 날짜 줄은 `2026.11`처럼 연·월만.
- **→ 연쇄 금지**: `A → B → C`는 `A, B, C`로. 흐름은 `s.flow`·순서도 도형으로. 순서가 없는 병렬 항목은 화살표 없는 `s.cards`로.
- 곁가지·미완 단서는 빼거나 계획 장으로 옮긴다. 표지 저자는 참여 연구자를 빠짐없이.
- 콜론은 제목·요지에 0, 장당 2 이하. 세미콜론·대시(— –, 띄운 하이픈) 금지. 나열은 쉼표, 가운뎃점은 장당 2 이하.
- 한국어 기반 + 기술어는 영어 원어(Bayesian optimization, EBSD 등). 한자어·번역투 금지. 사용자 문체(문체 스킬·예시)가 있으면 그 어휘를 AI 판단으로 바꾸지 않는다.
- **약어**: 청중이 아는 표준 약어(AI, GPU, DB, UTS, EBSD 등)와 기관 약칭은 풀지 않는다. 덱 고유·분야 밖 약어만 처음 한 번 세부·단계 설명·표 머리·캡션 중 한 곳에서 푼다.
- 금칙어(혁신적, 획기적, 핵심적, 게임체인저, 시너지, 티어1/2, 1.0·2.0 세대 라벨, 왜·어떻게 라벨 등, 전체 목록 STANDARD §7.2). 외부 자료에 내부 버전명·작업 이력 금지.
- **굵게·색 강조 금지**: 굵은 글자는 제목·요지·카드 필·표 머리·일정 날짜만. 숫자를 키우거나 색을 바꿔 강조하지 않는다.
- 출처는 논문·외부 figure 인용 장에만 `s.source()`로 1줄. 내부 자료 근거(파일 경로·계산)는 `manifest.csv`와 완료 보고에.
- **발표자 노트는 기본으로 비운다.** 사용자가 요청하면 발표 대본·예상 질문만 짧게. 다른 사람 자료를 옮긴 장은 그 사람 원본 노트만 둔다.
- **미확정 금액은 화면에 쓰지 않는다**(견적 전 추정액 등). 계획서 원문에 있는 확정 금액은 예외.
- **캡션이 ■와 같은 말이면 뺀다**: 한 장을 다 쓰는 도식·표는 캡션 없이 최대 크기로.
- 긴 글 상자(3문장 넘는 원문 인용 등)는 강제 줄바꿈 없이 자연 줄바꿈으로 두고, 뜻이 바뀌는 곳에서 문단을 나눠 빈 줄 하나를 둔다.

## 9. 그림
- **수정 가능한 형태 우선**(STANDARD §9.1 IM-05). 그림(이미지)으로 두는 것은 사진·화면 캡처·논문 figure·영상뿐이다.
  - **데이터 그래프 = 네이티브 차트**(XY 산점·꺾은선·막대). 음영 띠·많은 오차 막대처럼 네이티브로 못 그리는 것만 matplotlib으로 하고 이유를 manifest에 적는다.
  - **도식·순서도 = 도형**: 글은 상자 도형 안에 넣고(상자를 옮기면 글이 따라온다), 연결선은 `begin_connect`/`end_connect`로 상자에 붙인다. 판단(마름모, 예/아니오)과 되돌아가는 반복까지 넣는다. 판단 글에 '?'는 G8 fail이라 `2회 연속 하락`처럼 명사구로.
  - **다른 pptx(기존 덱 등)에 있던 도식은 캡처하지 말고 도형째 옮긴다**: 원 테마의 색·글꼴(schemeClr, +mn-/+mj-)을 명시값으로 풀고, 그림 관계를 다시 맺고, 그룹·표 크기를 같은 배율로 옮기고, 도형 id를 새로 매긴다.
  - **다른 사람의 결과 보고 pptx를 넣을 때는 최대한 그대로 옮긴다**: ■ = 그 사람 장 제목, 본문 = 그 사람 글 그대로(요약·바꿔 쓰기 금지). 바꾸는 것은 색(엔진 팔레트 `C`)과 글꼴(Paperlogy)뿐이다. 이 때문에 나는 콜론·굵게 게이트 fail은 원문 유지로 받아들이고 보고에 적는다.
  - **나중에 받을 화면·영상 자리**: 실제 비율(16:9 등)의 점선 빈칸 + `화면 추가 예정` + 캡션.
  - **영상**: GIF 원본 바이트를 `s.s.shapes.add_picture`로 그대로 넣는다(`s.figure`는 PNG로 바꿔 움직임이 사라진다). 슬라이드 진입 자동 재생은 타이밍 XML이 필요하다.
- **예측-실측 비교(parity)**: 가로축 = 예측, 세로축 = 실측. 1:1 선과 평균 오차를 그래프 안에 적는다.
- **작은 그래프 여러 개**: 조건마다 1칸에 그룹(V·H 등)을 색으로 겹쳐 칸 수를 줄이고 촘촘히 모은다.
- 원본 비율 유지·EXIF 회전·흰 테두리 트림은 엔진이 한다. 차트는 흰 배경 그대로 넣는다(투명화 `clear_bg=True`는 옅은 색이 지워질 수 있어 기본 끔). 사진은 JPEG 품질 90으로 들어간다.
- 다중 패널 figure는 패널 단위로 잘라 `assets/`에 저장해서 쓴다. 그림 속 글자가 반쯤 잘린 줄은 잘라낸다.
- 원본보다 1.25배 넘게 키우지 않는다(게이트 경고). 고해상도 원본을 구한다.
- 그래프를 다시 그리면 원자료 사본은 `assets/data/`, 추출은 덱 폴더 `prep_data.py`, 그리기는 `charts.py`에 두고 `manifest.csv`에 원자료 경로를 적는다. 원 프로젝트 폴더에는 쓰지 않는다.
- 생성 이미지(이미지 생성 AI)는 개념도·픽토그램이 꼭 필요할 때만. 프롬프트는 영어로 "PURE WHITE background, no text, no glossy, no neon, realistic lab photo tone". 도식이면 캡션에 "개념도". 편집이 필요한 도식은 엔진 도형(`flow`, `cards`, `timeline`, `s.shape`)으로.

## 10. 사용자가 직접 고친 pptx 다루기 (STANDARD §13 OUT-03)
1. 작업 폴더에서 사용자가 마지막으로 저장한 파일을 찾아 파일명과 시각을 먼저 알린다. PowerPoint로 열려 있을 수 있으니 **원본은 읽기만** 하고 사본으로 작업한다.
2. `python "<스킬>/scripts/pptx_diff.py" <이전 생성본> <사용자 수정본>`으로 고친 장·도형을 확인해 보고한다(장 수가 다르면 글 유사도로 장을 짝짓는다).
3. 사용자 파일 사본을 바탕으로 연다: `d = Deck("ppt", base=사본, workdir=HERE); d.protos = []` → 지시받은 장만 새로 만들어 끼우거나 그 도형만 고친다. 사용자가 고친 장·도형은 건드리지 않고, 지운 요소는 되살리지 않는다. 새로 만드는 장도 사용자가 고친 방향(노트 비움, 금액 삭제 등)을 따른다.
4. 저장 직전 사용자 파일을 다시 읽어 그 사이 더 고쳤는지 확인하고, `<원본>_v(n+1).pptx`로 저장한다.
5. 고친 방식에서 배울 규칙(문안 바꾼 방식, 지운 요소, 옮긴 배치)이 있으면 사용자에게 알리고, 동의하면 이 SKILL.md에 적어 둔다.

## 11. 함정
- **미리보기 ≠ PowerPoint**: 미리보기는 LibreOffice 렌더다. 자연 줄바꿈·차트 그리기가 PowerPoint와 조금 다르다. 네이티브 차트·도형 조정값을 쓴 덱은 전달 전에 PowerPoint로 한 번 열어 본다(Mac + PowerPoint면 `bash "<스킬>/scripts/pp_render_mac.sh" 입력.pptx 출력.pdf`로 실물 PDF를 뽑을 수 있다. 화면에 PowerPoint 대화상자가 떠 있으면 실패한다).
- **미리보기 글꼴 이름**: LibreOffice가 Paperlogy를 한글명(페이퍼로지)으로 아는 PC와 영문명으로 아는 PC가 있다. `preview.py`가 렌더 PDF를 보고 맞는 쪽을 골라 `~/.kims_ppt_preview_mode`에 기억한다. 게이트 G1이 "Paperlogy 외 폰트"로 fail하면 OS에 Paperlogy가 설치됐는지(`install.py`가 설치한다, 저장소 INSTALL.md) 먼저 본다.
- **Paperlogy 없는 PC**: 엔진이 맑은 고딕 폭까지 재서 줄이 넘치지 않지만 굵기는 사라진다. 외부 공유는 PDF가 기본이고, pptx는 PowerPoint "파일에 글꼴 포함"으로 저장해 보낸다(Paperlogy는 OFL이라 포함할 수 있다).
- **자동 축소 없음**: 넘치면 오류가 난다. 글자 크기를 낮추는 우회(XML 직접 수정 등)를 하지 않는다.
- **도형 조정값(adjustments)은 한 줄에 둘 이상 넣지 않는다**: `sh.adjustments[0], sh.adjustments[1] = a, b`는 avLst에 같은 값을 두 번 넣어 PowerPoint가 「복구」 창을 띄우고 도형을 버린다. LibreOffice 미리보기는 정상으로 보인다. 한 줄에 하나씩 넣는다.
- **차트 축 ID**: python-pptx 차트 템플릿은 축 ID가 음수다(스키마 위반). `d.save`가 차트마다 다시 매기므로 저장은 반드시 `d.save`로 한다.
- **PowerPoint에서 차트**: 글자 데이터 레이블을 차트 폭의 약 20%에서 접고, 눈금 글자가 축에서 약 21px 떨어져 세로 축 제목과 겹칠 수 있다. 왼쪽 여백 = 축 제목 + 눈금 글자 폭 + 24px 이상.
- **px와 pt**: 이 바탕 파일은 가로 1058.25pt = 1920px(1pt = 1.814px)다. 글 폭과 줄 높이를 직접 계산할 때는 `slide_width`에서 구한다. Paperlogy 줄 간격 100%의 줄 높이는 글자 크기의 1.2배다.
- 표지·간지·감사 원형의 배경 그림과 로고 자리(`LOGO:*`)는 지우거나 옮기지 않는다. 로고는 `Deck(logo=)`·`logo.py`로만 바꾼다.
- **XML을 직접 고친 덱**(다른 pptx에서 도형을 옮겼거나 바탕 덱에 장을 끼운 경우): 저장 뒤 PowerPoint로 열어 복구 창이 안 뜨는지 확인한다. OOXML 검증기가 있으면 돌려 새 오류가 0인지 본다.
- **18장 이상 큰 덱**: build.py에 표지·목차를 두고 장 묶음을 `part_a.py`, `part_b.py`… 함수(`def build(d): ...`)로 나눠 서브에이전트에 병렬로 맡길 수 있다. 모두 같은 엔진을 import하고(복사 금지), 각자에게 목차 문자열·담당 장 사양·이 SKILL.md와 STANDARD.md 경로를 준다.
